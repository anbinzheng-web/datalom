# 平台账号与会话调度

当前通用 Worker 仍仅接入 TikTok；后台按账号真实 platform 字段展示，不代表其他平台已经接入通用任务执行。

任务提交时绑定 accountId。领取时通过 SQLite 原子事务取得该账号的独占租约（60 秒、执行期间续租），执行期间固定会话版本和代理。不会因 429 换账号重放任务。失效或挑战状态暂停取用，禁用账号不会被冷却流程重新启用。

管理后台“平台账号 → 调度设置”可调整账号请求间隔，范围 3000–3600000 毫秒。GET/PUT /api/accounts/:id/scheduling 读取或保存策略，继承管理接口鉴权。单账号并发固定为 1，策略持久化在控制面数据库；已有预约不会被缩短，新预约应用新策略。

生产默认请求间隔为三秒，仍保留已有共享代理及平台接口时隙约束。连续任务触发 RATE_LIMIT 时按一分钟、两分钟、四分钟逐次冷却，最大一小时；一次完整任务成功后重置连续次数。已预约的更长等待不会被冷却缩短。目前尚未解析 Retry-After，也没有跨账号的共享出口 429 冷却。

这是绑定账号的会话分配，不是自动轮换池。自动选择账号、按上游额度分组和多平台调度仍需后续实现；限速能降低请求冲突，不能保证上游永不返回 429。
