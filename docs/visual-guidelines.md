# 官网视觉规范

本规范适用于 `apps/web` 官网、文档入口和共享营销组件。

## 设计基础

- 采用确认的 refined-2 方向：冷白页面、靛蓝品牌、抽象 D 标志和真实数据结构预览。品牌源文件只在 `packages/shared/brand` 维护，通过同步脚本分发。
- 官网标题、正文和控件使用本地加载的 Inter（400 / 500，`--font-site`）；代码、接口示例与技术标签使用 IBM Plex Mono（`--font-code` / `font-mono`），避免大标题和长段落使用等宽字体。中文回退至系统中文字体。SVG 品牌字标保持独立造型。字体许可证随资源保留。
- 字号使用固定断点，不随视口连续缩放；字距为 0，只使用 400 和 500 字重。

| 层级           | 桌面    | 手机              | 行高     |
| -------------- | ------- | ----------------- | -------- |
| 首页展示标题   | 68px    | 36px（平板 56px） | 1.08     |
| 普通页面标题   | 56px    | 36px              | 1.08–1.2 |
| 区块标题       | 40px    | 28px              | 1.2      |
| 组件标题       | 20–24px | 20–24px           | 1.3      |
| 正文           | 16px    | 16px              | 1.7      |
| 控件与辅助文字 | 12–14px | 12–14px           | 1.4–1.6  |

- 普通页面和区块标题分别使用 `--text-page`、`--text-section`；紧凑工作台不使用展示级标题。
- 颜色以冷白、靛蓝和蓝灰为基础。品牌色用于主操作和关键状态，紫、青、琥珀仅作语义点缀，不用多色装饰填充页面。
- 组件默认无可见边框，使用浅色底、留白和浮层阴影区分层次；聚焦等必要描边统一 1px；普通控件圆角 6px，容器 8px，重点展示面 12px，禁止随意使用超大圆角或胶囊形容器。
- 阴影只用于浮层、对话框和需要抬升的主要展示面：`shadow-sm`、`shadow-md`、`shadow-lg` 三档；普通区块保持无阴影。
- `Button`、`Input`、`Select`、`Textarea` 和 `Field` 使用共享 UI primitive，页面不得重新定义控件外观。

## 组件约定

| 组件                | 结构与状态                                                                                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Button / ButtonLink | size 支持 xl 44px、lg（默认）40px、md 36px、sm 32px、xs 28px，含边框；主按钮靛蓝，次按钮浅灰底无描边，轻按钮透明；加载时禁用并保留标签                                                                |
| Input / Select      | 与 Button 共用五档 size 和含边框高度，6px 圆角、透明 1px 边框占位，默认浅灰底；hover 加深底色；focus 切换白底、使用品牌边框及贴边 3px、10% 品牌色光晕，无默认阴影；错误态浅红底，聚焦时红色边框与光晕 |
| Textarea            | 与 Input 共用五档 size 基础高度，允许纵向调整；多行内容可通过 className 设置业务所需高度                                                                                                              |
| Field               | 标签、控件、说明依次排列；错误通过 aria-invalid 与 aria-describedby 关联                                                                                                                              |
| 分段选项            | 相同尺寸，使用 aria-pressed 或 aria-selected；选择态使用品牌浅底与品牌文字，无可见描边，不因内容切换改变尺寸                                                                                          |
| 表格                | 复用 Table primitive；中性表头、白色与浅灰交替行，无外框和行分隔线，正文 12–14px；窄屏由外层容器横向滚动                                                                                              |
| Modal               | 最大宽度 560px、12px 圆角、最高一档阴影，无外框及头尾分隔线；支持 Escape、焦点约束与关闭后焦点恢复                                                                                                    |
| Accordion           | 浅色底与间距区分条目，无分隔线；保留键盘操作与展开反馈                                                                                                                                                |
| Message             | 信息、成功、警告、错误分别使用语义色；成功色独立于品牌色                                                                                                                                              |

按钮和链接的键盘焦点使用 3px 靛蓝 outline，偏移 3px；表单控件使用贴边浅色光晕与品牌边框，避免双重粗描边，强制颜色模式保留系统 outline；禁用态降低透明度并保留可辨识文字。`/design-system` 展示同一套生产组件与交互状态。

## 样式实现

- 普通布局、间距、字号、颜色、边框、圆角、阴影、响应式和交互状态直接使用 JSX `className` 中的 Tailwind 工具类；简单渐变也使用工具类。
- 不为普通页面区块创建 CSS 选择器，再用 `@apply` 包装整套布局。复用通过 React 组件和明确的样式变体完成。
- 原生 CSS 仅保留复杂关键帧动画、难以用工具类清晰表达的组合视觉效果，以及 reset、字体、设计 token、Tailwind 配置等全局基础定义。复杂效果需简短说明保留 CSS 的原因。
- 修改已有样式时，将本次涉及的普通样式迁移到工具类并移除对应旧规则；不在 CSS 文件末尾不断追加覆盖，不依赖提高选择器优先级修补布局。
- 确认 Tailwind 扫描覆盖实际源码路径。布局变更须验证生成样式及桌面、窄屏实际效果；类型检查通过不能代替视觉验证。

## 链接与按钮

- 链接和按钮使用清晰的文字表达动作，不在文字末尾添加 `↗`、`↖` 或其他装饰性外链箭头。
- 外部链接与站内链接统一使用相同的文字链接样式；是否外部跳转由链接行为和 `target`/`rel` 属性表达。
- `→` 只用于明确的流程图、步骤关系或数据流示意，不用于普通链接文案。
- 图标只有在表达独立操作、且不重复文字含义时才使用；不要为了装饰给每个卡片或链接加图标。

## 页面构图

- 首页首屏优先使用清晰的单一视觉焦点，避免左右两侧堆叠同等权重的信息。
- 装饰应保持克制，服务于层次和阅读顺序；不使用无意义的标签、统计或重复说明填充空间。
- 文字必须与容器匹配，标题、卡片和按钮在窄屏下不得溢出或互相遮挡。

## 文案

- 每个区块只保留能帮助用户理解产品或完成下一步的文案。
- 避免重复表达同一价值、状态或 CTA。
- 产品状态、价格、平台数量和支持能力集中维护，页面不要多处手写互相矛盾的版本。
