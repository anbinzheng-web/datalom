# 前端应用划分

当前 `apps/admin-web` 是我们的管理后台（包名 `@datalom/admin-web`），不是官网首页，也不是客户用户后台。它包含账号会话、代理验证、接口研究、签名验证和 Worker 诊断，其中研究能力只是管理后台中的内部工具模块。

产品前端按权限和业务职责拆分为四个应用：

| 应用     | 目标目录                                | 主要内容                                                             | 访问范围     |
| -------- | --------------------------------------- | -------------------------------------------------------------------- | ------------ |
| 官网与用户入口 | `apps/web`（Next.js） | 首页、数据集目录、样例、价格、文档、登录和用户后台 | 公开/登录用户 |
| 管理后台 | `apps/admin-web`（包名 `@datalom/admin-web`） | 用户、订单、数据集发布、采集批次、账号会话、接口研究、代理和执行诊断 | 内部管理角色 |

管理后台使用最新版本的 Ant Design，采用 React 构建，优先复用 Table、Form、Drawer、Modal、Tag 和 App 等基础组件。接口研究、RoxyBrowser 提取和 Worker 诊断都作为后台的受限模块存在。

## 本地采集器推送

RoxyBrowser 配置示例在 `config/roxy.example.json`。将实际连接信息放入 Git 忽略的 `config/roxy.json`，按 Profile 的 `dirId` 关联其 `platforms`。`pnpm roxy:config` 目前只校验配置结构，不会启动浏览器，也不会设置 Worker 并发。

本地 RoxyBrowser 连接器负责读取平台 Cookie、Profile 代理和观测环境，然后通过管理 API 推送。当前入口是 `POST /api/roxy/profiles/:id/extract`：服务端完成加密存储、账号版本更新和证据记录，响应只返回脱敏账号与警告。后续独立采集器可以复用同一管理 API 契约，不需要访问 SQLite 文件。

四个应用可以共享设计系统、认证组件和 API 类型，但不能共享权限边界。研究工作台不应出现在公开导航中，也不应向客户暴露账号会话、代理配置或研究证据。

迁移顺序：先保留现有研究工作台并完成命名隔离；再建立 Next.js 官网；随后建立用户后台和运营后台。官网使用服务端 metadata 和公开数据集页面获得 SEO，后台页面不承担 SEO 目标。
